# GOAI 工业制造方向演示脚本

## 核心叙事

ForgeGuard 不是轴承分类器，也不是工业聊天机器人。它是运行在边缘节点上的证据驱动运维 Agent 平台：将设备信号、工业知识、生产、库存、人员、安全和环境约束统一到可审计决策中，由人批准并用维修后数据证明真正恢复。

## 四分钟主路径

1. **异常进入**：Jetson 或跨平台边缘节点实时回放公开真实数据；质量门控通过；模型生成证据。
2. **Agent 分析**：诊断、RUL、安全、可持续和韧性 Agent 并行形成结构化结论。
3. **决策竞技场**：比较立即停机、受限运行、补采证据等方案；展示安全、韧性、能耗、废品、成本和停机。
4. **人机共治**：授权人员批准方案；平台创建工单和 LOTO/PPE 检查清单。
5. **验证闭环**：回放维修后正常数据；验证 Agent 比较前后证据；通过则关闭，失败则重开。

## 必演失败分支

输入低质量、削波或跨模态冲突数据，系统必须：

- 标记证据质量问题。
- 阻止确定性维修结论。
- 请求重新采集或人工复核。
- 保留失败工具调用和审计记录。

## 评委追问准备

- 为什么是 Agent 而不是普通工作流？答：Agent 具有明确职责、动态证据缺口、工具调用、结构化输出和受治理状态协同；确定性状态机负责安全不变量。
- 为什么不用一个大模型完成所有任务？答：实时信号、RUL、安全规则和业务约束分别使用最合适的模型和工具，LLM 只承担语言理解与解释。
- 是否控制真实设备？答：只读接入和决策支持；高风险动作必须人工批准，默认不直接控制设备。
- 准确率是否代表工厂表现？答：公开数据、合成数据和自建台架结果分开报告，不外推未验证结论。
