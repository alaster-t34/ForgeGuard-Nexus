# 可公开解释的新增创新范围

## 与既有轴承项目的边界

既有 RV1126B、IIS3DWB、RKNN、WDCNN、FP-FLNet、旧数据集和旧 PyQt 界面属于前期资产，可作为可选边缘适配器或模型来源，但不作为 ForgeGuard Nexus 5.0 的全新贡献重复申报。

## ForgeGuard Nexus 5.0 新增贡献

1. **工业 5.0 三维价值决策模型**：将人员安全、系统韧性和可持续影响直接纳入维护方案评分，而不是只优化准确率、成本或停机。
2. **证据质量优先的 Agent 状态机**：低质量、削波、缺失模态和跨模态冲突会阻止过度自信结论并触发补采。
3. **结构化多 Agent 协同**：诊断、可靠性、安全、可持续、韧性、规划、治理和验证 Agent 具有独立契约与审计轨迹。
4. **生产—库存—人员—设备联合决策**：方案需要查询生产缓冲、备件、技能认证和班组可用性。
5. **受治理的高风险工具调用**：工单和生产影响类工具默认阻断，人工批准后才可执行。
6. **维修后证据闭环**：工单完成不是终点；前后数据验证通过才关闭事件，否则自动重开。
7. **跨平台边缘运行时**：Windows、Arch/Debian、Jetson 共用数据契约、离线 spool、ONNX/TensorRT/CPU 回退接口。
8. **本地优先工业 Copilot**：无 LLM 也可完整运行；可选本地模型只增强语言理解，不能绕过政策层。
9. **持久化工业业务模型**：资产、事件、库存、生产、人员、工单和审计统一存储于 SQLite/PostgreSQL 兼容仓库。
10. **产品级工业控制台**：从单设备 Demo 重构为指挥中心、事件驾驶舱、决策竞技场、移动工单、环境看板、边缘节点和治理中心。

## 不应宣称的内容

- 未经真实企业现场验证的工厂准确率。
- 未构建的神经网络 TensorRT engine 已经集成。
- 合成数据结果等同于物理台架或现场结果。
- Agent 已经具有安全认证或可自主控制生产设备。
- 厂商宣传案例中的节能、效率数字属于本系统实测结果。
