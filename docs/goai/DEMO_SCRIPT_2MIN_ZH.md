# ForgeGuard Nexus GOAI 2 分钟 Hero Demo 脚本

目标：两分钟内让评委看到“工业异常如何变成受治理、可执行、可验证的维护行动”，而不是展示功能菜单。

## 0:00-0:12 - 一句话建立问题

画面：运行总览 + 设备状态。

口播要点：传统预测性维护可以告诉我们“设备可能故障”，但现场真正要决定的是：能不能停、什么时候停、有没有备件和合格人员、维修后怎么证明恢复。

## 0:12-0:28 - 异常和证据进入

画面：数据检测/场景库，启动“轴承外圈故障”场景。

展示：

- 振动/运行条件进入系统；
- 数据质量门通过；
- Evidence 形成；
- 故障类型、置信度、健康度/RUL 风险出现。

口播要点：Agent 不直接相信任意输入，先判断证据质量，再进入诊断与风险分析。

## 0:28-0:52 - 多 Agent + 工具调用

画面：事件详情 / Agent Trace / Tool Calls。

快速展示：

- Diagnosis / Reliability Agent；
- FMEA 知识检索；
- Inventory 查询；
- Production window 查询；
- Technician skill / safety constraint。

口播要点：诊断结果不是终点，系统把设备证据和库存、生产、人员、安全约束统一到同一个任务上下文。

## 0:52-1:15 - 决策竞技场

画面：多个维修方案比较。

展示至少两个方案，例如：

- 最近安全窗口停机更换；
- 受限运行并加强监测；
- 证据不足时重新采集。

强调安全、停机、成本、人员、备件和风险差异。

口播要点：Agent 生成候选行动，但高风险动作不能自行执行。

## 1:15-1:30 - 人工审批 + 工单

画面：授权人员选择方案并批准，随后创建工单。

展示：审批记录、工单、LOTO/PPE/技能要求。

口播要点：这是 Human-in-the-loop 的硬治理门，不是 Prompt 约束。

## 1:30-1:48 - 维修后验证闭环

画面：回放维修后正常数据，触发 Verification Agent。

展示：维修前/后证据对比、验证通过、事件关闭。

口播要点：工单完成不等于故障解决；只有维修后数据验证恢复，事件才能关闭，否则自动重开。

## 1:48-2:00 - 失败分支

画面：切换到削波/掉点/冲突证据场景。

展示：质量告警、安全门触发、拒绝确定性结论、请求重新采集/人工复核。

结尾一句：ForgeGuard 的价值不是“多一个工业 AI 回答”，而是让异常从证据进入，到人审批，再到维修后验证形成可追溯闭环。

## 录制要求

- 主视频建议 1080p，90-150 秒；
- 不要在主视频里逐个介绍 13 个 Agent；
- 不要长时间停留在代码或架构图；
- 每次工具调用只展示名称、输入约束和结果摘要；
- 至少保留一次失败/拒识路径；
- 不展示真实密钥、个人信息、企业内部数据或浏览器账户信息。
